# 定位修复验证

定位服务收到有效目标、GPS 与 network 均完成首次注入后才报告启动或传送成功。服务使用唯一的定位线程和调度循环，按单调时钟计算位移；页面重建只解除绑定，重新打开页面后连接已有会话。通知栏提供停止入口。

## 自动检查

- `MapUtilsTest`：国内坐标反复往返、国内沿海地点、境外坐标、米制偏移、极区和跨日期变更线移动、无效输入。
- `MockLocationEngineTest`：无目标时禁止发布、半推速度、延迟调度、停止、速度切换、传送和单步移动。
- `LocationResultPolicyTest`：只接受有效成功结果，临时失败最多重试三次，间隔为 1、2、4 秒。
- `HistoryDatabaseTest`：收藏、历史迁移及原始 WGS84 坐标保存。

前三项是纯 Java JUnit 测试，可以独立执行，无需生成 APK。本次也使用 Android API 34 和项目实际依赖进行了 Java 接口编译检查，并以 SQLite 宿主适配运行数据库回归；宿主适配不等同于 Android 实机仪器测试。未使用浏览器插件或打包方式测试。

## 实机复核场景

1. 未选择目标时不能启动；启动失败或传送失败时不得显示成功、写入成功历史。
2. 连续切换目标位置，确认更新频率不随操作次数增加；快速停止再启动，确认旧服务清理不会移除新服务的提供器。
3. 半推、全推、松开、触摸取消、锁定移动、方向单步与切换速度，核对位移、速度和方向；传送后应停止之前的移动。
4. 移动时打开悬浮地图，当前位置持续刷新；刷新不得清除另选的目标或反复移动地图视角。
5. 旋转屏幕、切换应用、重建页面、从通知重新进入，确认会话持续且按钮状态正确；通知停止后提供器和悬浮窗应清理。
6. 撤销模拟位置或悬浮窗权限、关闭定位服务，确认会话停止并给出原因。
7. 断网后，通过手动坐标或历史位置启动和传送；地址解析失败不得丢失已确认的位置记录。
8. 测试约略定位授权、通知权限拒绝、Android 14 及以上系统的前台服务行为，以及锁屏长时间运行。

## 坐标边界

原始 WGS84 输入和历史记录中的 WGS84 数值保持不变，地图转换仅用于显示。区域判断使用 Natural Earth 50m 简化轮廓及少量沿海补充，避免矩形范围将新加坡、首尔等地误识别为百度坐标地区。轮廓不是精确边界数据，边境、近岸和小岛仍需结合百度 SDK 的实际坐标返回方式核验。

数据来源：[Natural Earth vector](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_50m_admin_0_countries.geojson)。
